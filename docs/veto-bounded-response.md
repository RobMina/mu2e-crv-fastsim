# Bounded source-qualified saved-photon response

This is a diagnostic-only executor and bounded real-asset validation path. It
changes no production default, optical draw, saved registry, fixed-stock baseline,
or previously frozen response helper. The retained-sample campaign remains gated.

## Whole frames and identities

`bounded_response.run_arm` takes the **complete frozen registry**, exact selected
registry rows, saved keyed photons, and complete per-input detector calibration.
It binds the expected registry digest, validates original optical roots/seed and
frame membership, and constructs every status-live channel for every selected
frame. Quiet and zero-output frames remain in an explicit frame ledger. An entirely
status-dead frame also remains; output-derived domains never define exposure.
Legacy helper event labels and downstream seeds come from the frozen registry,
not a batch-local reranking. Physical source identity is restored on all stages.

Whole-frame recovery histories are never split. The SiPM is the existing fixed-
integer-pixel, zero-trap, keyed breadth-first grouped-crosstalk diagnostic law, not
stock queue/RNG equivalence. `bounded_sipm` enforces explicit photon/thermal/
candidate/attempt/generation/recovery-state budgets before the named allocations.
`bounded_waveform` and the separate width-bucketed diagnostic fit enforce cell and
numeric-domain admission. A cap or numerical exception means incomplete output,
never clipped histories, dropped frames, relaxed tolerances or changed exposure.

## Saved smoke validation

`python3 -m crvfastsim.veto.saved_qualified_response` requires explicit plan/smoke
summary hashes, pinned photon-map/template assets, and a new output directory.
It repeats saved-only plan and optical admission (no optical generation), uses all
9,000 registry labels but only the original four smoke frames, and tests the saved
optical seeds 3027000 and 3027001. The downstream seed equals the optical seed in
each pair and is transformed by the complete registry contract. This two-pair
schedule is not an independent optical-versus-downstream variance decomposition.

For each seed and timing arm (historical, arrival-only, rejection-only, both stock
timing operations), it runs the full four-frame domain and two disjoint alternating
frame partitions in reversed order. Thermal rate is explicitly `1e-4 / ns` on all
status-live detector channels, from relative 100 through 1500 ns. This new domain
is different from earlier optical-channel-union controls. Full digi tails survive;
the start window remains inclusive 200..1500 ns and no SiPM lower cut is added.

All physical fields are checked exactly on candidates, attempts, charges, digis,
pulses, conditions, phases, clusters, waveforms, fit samples and frame coverage.
Local cluster/waveform ranks are replaced by structural source-qualified start
keys; these are not pulse truth identities across arms. Analog samples marked
`valid=false` are nonphysical batch-padding cells and excluded from partition
comparison, but remain saved unchanged. Physical analog samples, full fit samples,
all fit fields and flags are compared without numerical tolerance. Different arms
are compared structurally, not required to be identical.

## Output and scope

The run publishes a bounded transaction in `run/`, with separate bounded
transactions for eight arm/seed domains. Each child contains full and partitioned
stage tables plus its exact-comparison ledger; the top receipt binds all child
receipts. The fixed caps are 2 MiB for run metadata plus 32 MiB per child, **258 MiB
maximum logical bytes through these writers**. Failed artifacts remain on disk and
are not reusable physics results. Existing directories are never overwritten.
Read `veto-batch-artifacts.md` for receipt validation and crash-durability limits.
No raw inputs are staged and nothing runs automatically on a cluster.

`python3 -m crvfastsim.veto.saved_qualified_report EXISTING_RESPONSE --out NEW_JSON`
validates saved completion protocols, byte accounting, all required code/input
hashes and source snapshots, the approved frozen waveform helper, and authoritative
registry/conditions/phases. It checks numeric stage schemas, original optical-root
lineage, physical sample support and coverage before recomputing exact full-versus-
partition comparisons. `--compact` prints a smaller counts/comparison/frame view;
the output file retains the complete verification report. Optical, avalanche,
waveform and fit products are not regenerated by this verifier. Hash-bound response
arithmetic is still a generation measurement, not something independently rerun by
saved-only verification. The source admission chain and negative tests prohibit
both top-level and low-level generation entry points.

The run records code/input hashes, complete configuration, seed schedule, resource
caps and timings. Two draws still represent four unique exposure frames, not eight
independent exposures. Exact partition checks certify only the tested domains and
environment, not arbitrary batch arithmetic or cross-platform equality. These
results do not estimate F, response-seed uncertainty or finite-library covariance,
close CE exposure, or authorize a full retained-sample campaign.
